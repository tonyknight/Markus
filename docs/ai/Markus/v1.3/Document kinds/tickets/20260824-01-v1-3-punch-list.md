## Description

Post-test punch list after v1.3 Document kinds shipped. One ticket, five fixes, in order. Product override: File → New is a single command plus a centered type picker (default Markdown), not one menu item per kind.

## Acceptance criteria

- [ ] File → Open accepts `.md` files tagged `public.markdown` as well as `net.daringfireball.markdown`.
- [ ] File → New is one command (⌘N). A centered dropdown picker defaults to Markdown; Create opens that untitled. Per-kind New menu items are gone.
- [ ] Nested/minified JSON does not trap in `JSONScanner.finishContainer`.
- [ ] Open Folder's library tree lists all shipped document kinds, not Markdown only.
- [ ] Opening typical HTML/SVG (including single-line nested markup) does not trap. Folding stays kind-flexible (`SyntaxProfile`); scanners and `FoldingTextView` never construct inverted `Range`s.

## Context

Worktree: `.worktrees/v1.3-punch-list` on `bora/markus-v1-3-punch-list`. Origin branch: `main`. NO TDD. Gate is xcodebuild Debug build.

Cause of (3) and (5): scanners build `openerEnd..<closerEnd` *before* checking order. `endOffset(ofLine:)` is the end of the opener line (start of the next line, or EOF). Nested same-line containers have `closerEnd` in the middle of that line, so the range is inverted and Swift traps. Do not need the reporter's JSON file.

Folding is already per-kind (`SyntaxProfiles.profile(for: documentKind)`). The HTML/SVG crash is inverted fold extents, not Markdown-only fold code.
