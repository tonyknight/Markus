# Markus v1 — Planning

Feature set for v1 is agreed. Architecture (native Apple frameworks vs a shared
non-UI core, text view, parser) is the next conversation. Do not treat this
file as a clone spec for any third-party editor; that work is a speed and
honesty *baseline*, not a product to reproduce.

## Background

Markus is a free, open-source, native Markdown app for **macOS, iOS, and
iPadOS**. It opens ordinary files on disk. There is no account, no vault, no
telemetry, and no subscription.

Most people **read** Markdown more than they edit it. v1 therefore opens in
**Preview** and treats folding as a reading tool: on a phone or iPad, collapsing
headings and fenced code is how a long document stays navigable. Source is
there when the user needs to change the file.

The honesty bar is a native, file-based Markdown editor: truthful preview, plain
`.md` on disk, no Electron. Markus exists because that bar does not include
**heading and fence folding**, and because it does not ship on iPhone or iPad.

License: MIT (see `LICENSE` in the repo root).

## Goals

- Ship one product on Mac, iPhone, and iPad that feels native on each.
- Render **GitHub Flavored Markdown** truthfully. If preview is wrong, v1 has
  failed.
- Let people **fold headings and fenced code blocks** while reading or editing,
  on every platform.
- Keep a clean UI: **Source or Preview**, never both at once. Default is Preview.
- Open a **single Markdown file** or a **folder** of Markdown files, with a tree
  for the folder case.
- Theme the app: six named built-ins plus one simple custom theme.

## Non-goals

v1 will not include:

- Side-by-side Source and Preview on any platform
- PKM (wikilinks, graph, vault, bidirectional links)
- AI, plugins, or user key remapping
- Math and Mermaid (easy to render badly; fights truthful GFM)
- Raw HTML as a first-class preview feature
- Windows or Linux
- A 180-language code editor (fenced blocks inside Markdown are enough)
- Multi-cursor
- Project-wide search across the folder
- PDF / RTF export
- List, block-quote, or `#region` folding (unless it falls out of the same
  index for free later)
- Copying another app's chrome, theme names, or palettes

## Target users

People who keep Markdown as files — notes, specs, READMEs, long drafts — and
want a fast native app instead of a browser-shaped editor or a notes vault.

They already know Markdown. They do not want a new dialect. They open a file
from Finder or Files, or a folder of `.md` files, read it, fold the parts they
do not need, and edit only when something is wrong.

Mac is the dense desktop: tabs, line numbers, minimap, keyboard. iPad and
iPhone are the same documents, Preview-first, with folding on a smaller screen.

## User stories

- As a reader, I open a `.md` file and land in Preview so I can consume the
  document immediately.
- As a reader, I fold a heading section or a fenced code block in Preview so a
  long file stays scannable, especially on a phone.
- As a reader, I jump to a heading from an outline so I do not have to scroll
  the whole file.
- As a writer, I switch to Source, edit GFM, and save; the file on disk is the
  full unfolded Markdown.
- As a writer, I fold in Source using the gutter, and find/replace still works
  across folded regions.
- As someone with a notes folder, I open that folder and pick a Markdown file
  from a tree of `.md` files (including nested folders).
- As someone with one file, I open it from Finder or Files and get a normal
  document, with the tree hidden or empty.
- As a Mac user, I use tabs, line numbers, and a minimap while staying in one
  mode (Source or Preview).
- As an iPhone or iPad user, I switch Source/Preview with a slider (or
  equivalent), not a split view.
- As someone who cares about look, I pick one of six named themes, or set a
  custom background and light/dark text, and see a live sample before applying.

## Constraints

- **Files are the source of truth.** Folds, theme, and window state live in app
  storage, never by rewriting the Markdown.
- **One mode at a time.** Source XOR Preview. No split, no dual pane.
- **GFM is the dialect.** CommonMark plus tables, task lists, strikethrough,
  and footnotes. No house format.
- **Native Apple clients** for macOS, iOS, and iPadOS. Not Electron, not a
  web-view editor.
- **Folding must work without line numbers** on iOS/iPadOS, because numbers are
  optional there.
- **Preview folding uses source structure.** Gutter numbers (when shown) are
  source line numbers so they match Source and go-to-line.
- Engine and UI toolkit are **not decided** in this file. A Rust document core
  is a candidate if it serves all three platforms; Apple frameworks only is
  also in bounds. Choose that in architecture, against this feature set.

## Success criteria

v1 is working when all of the following are true:

- Preview of a GFM fixture (headings, tables, task lists, strikethrough,
  footnotes, fenced code) matches the dialect we claim. No math/Mermaid required.
- On Mac, iPhone, and iPad: open a long `.md`, land in Preview, fold/unfold a
  heading section and a fenced block, fold all / unfold all, switch to Source
  and see the same folds, save, and the file on disk is complete and unfolded.
- Mac Source and Preview both show a line-number gutter with fold chevrons.
- iPhone/iPad can hide line numbers and still fold from a slim gutter in both
  modes.
- Opening a single file and opening a folder both work; the folder tree lists
  only Markdown (`.md`, `.markdown`, `.mdown`, `.mkd`), including nested
  folders, and omits other files and dotfiles.
- Theme picker: six named cards, live sample preview, apply on click/tap; plus
  one custom theme (background color, text style Auto / Light / Dark).
- Mac has tabs and a minimap (current mode) that respects folds. iPhone has
  neither tabs nor minimap. iPad has no tabs; minimap is not required.
- No account, no network requirement, no telemetry for core editing.

## v1 feature set

### Must

1. **Truthful GFM preview** — CommonMark plus tables, task lists, strikethrough,
   footnotes. Files stay plain Markdown on disk.
2. **Theming** — six named built-in themes (background plus colors for Markdown
   elements: headings, body, links, inline code, fences, lists, fold markers).
   One custom theme: background color and text style Auto / Light / Dark. Card
   picker with a live sample document; hover-preview on Mac, apply on
   click/tap. Names and palettes are Markus's, not another product's.
3. **Folding** — ATX headings (hide through the next heading of the same or
   higher level) and fenced code blocks (keep the opening fence and a short
   placeholder). Fold all / unfold all. Available in **Preview and Source** on
   **every platform**. Shared fold state across the mode switch. Gutter
   chevrons. Disk always stores the full source.
4. **Source or Preview, never both** — default **Preview** on all platforms.
   Mac: Source / Preview controls in the document title bar. iPhone / iPad: a
   slider (or equivalent) into Source.
5. **Open a file or a folder** — a single Markdown file is a normal document
   (tree hidden or empty). A folder shows a tree of Markdown only, including
   nested folders. No vault.
6. **Line numbers and fold rail**
   - **Mac:** line-number gutter with fold chevrons in **both** Preview and
     Source. Numbers are source lines.
   - **iPhone / iPad:** line numbers optional in both modes. A slim fold gutter
     remains when numbers are off.
7. **Minimap** — macOS yes, in the current mode, and it must hide or compress
   folded ranges. iPad nice-to-have (not required for v1). iPhone no.

### Should (quality of life once the spine exists)

- Outline jump (same heading index as folds)
- Find / replace that still works across folded regions
- Open, save, revert, recents (files and folders), UTF-8, autosave
- Tabs on **Mac only**
- Go to line, status bar, zoom
- Keyboard shortcuts for fold, outline, Source/Preview, and the tree
  (including a hardware keyboard on iPad)

### Later

- Project-wide search, multi-cursor, PDF/RTF export
- Highlighting for many languages beyond Markdown fences
- Distraction-free / typewriter modes
- iPad minimap if it misses v1
- Folding lists and block quotes
- Persist-and-restore of richer window layout beyond fold state and recents

### Skip (v1)

- Side-by-side Source + Preview
- PKM, AI, plugins, key remapping
- Math, Mermaid, raw HTML as first-class preview
- Windows / Linux
- Language-level folds inside fenced code

### Platform matrix

| Capability | Mac | iPad | iPhone |
|---|---|---|---|
| Preview default; exclusive Source / Preview | yes | yes | yes |
| Fold headings + fences in both modes | yes | yes | yes |
| Line numbers (fold rail) | always, both modes | optional | optional |
| Slim fold gutter without numbers | n/a (numbers on) | yes | yes |
| Folder tree (Markdown only) | yes | yes | yes |
| Tabs | yes | no | no |
| Minimap | yes | later / nice | no |
| Theme picker | yes | yes | yes |
| Title-bar Source / Preview | yes | no (slider) | no (slider) |
