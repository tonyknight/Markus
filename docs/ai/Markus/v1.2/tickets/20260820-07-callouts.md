## Description

Preview has no callout element, so a Custom callout color would be a lie. Parse GitHub-style alerts (`> [!NOTE]`, TIP, WARNING, IMPORTANT, CAUTION). One `tokens.callout` color for chrome (background/border/label). Types differ by keyword and SF Symbol, not five wells. Unknown `> [!FOO]` is a normal block quote. Not a fold type. If detection paints every quote as a callout, stop and reopen design (Requirements risk).

### T01: Parse GitHub alerts (NOTE, TIP, WARNING, IMPORTANT, CAUTION)
Detect GitHub alerts only in the Preview structure walk (`PreviewStructureCollector`), not as a fold type and not in `MarkdownParser` / `BlockIndex`. cmark-gfm has no alerts extension; a `CMARK_NODE_BLOCK_QUOTE` whose **first paragraph’s first line** (plain text up to the first soft/hard break, trimmed) is exactly `[!NOTE]` / `[!TIP]` / `[!WARNING]` / `[!IMPORTANT]` / `[!CAUTION]` (case-insensitive) becomes one `ParsedPreviewBlock.kind.callout`. Do **not** match `[!TYPE]` in the middle of a quote, extra text on the marker line, nested quotes as a whole, or unknown tags — those stay `.paragraph(..., quoted: true)` so ordinary `> quotes` are never painted as callouts (Requirements risk). Emit a single block spanning the blockquote’s source lines; strip the marker from body inlines; do not walk those children as quoted paragraphs. Renderer must compile: stub the new kind as labeled body text (no chrome yet). Source mode untouched.
