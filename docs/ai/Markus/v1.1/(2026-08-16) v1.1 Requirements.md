# v1.1 Requirements

Product intent lives in `(2026-08-16) v1.1.md`. This file is the agreed
architecture, testable requirements, and the Tasks Breakdown that becomes
tickets. Implementation plans are written **on each ticket**, not here.

Architecture: **C, refined.** Native Apple UI, Markus-owned TextKit 2
editor, cmark-gfm parser, Swift block index — unchanged from v1. v1.1
adds three deliberate changes: Preview renders through
`NSTextContentStorageDelegate` paragraph substitution, the macOS main
menu is AppKit, and text input exists in Source only.

## Overview

v1.1 is a correction-and-completion release targeting **macOS**. It makes
the app evaluable: a document window that behaves like a Mac app, a
Preview that renders Markdown rather than colouring its syntax, folding
finished to the v1 specification, chrome that does what its labels claim,
performance that holds on a 5 MB document, and — last — the ability to
type.

The shared editor, parser, and block index are cross-platform. Changes
there must keep iOS and iPadOS building and green. No new iPhone or iPad
UI is in scope.

## Goals

- macOS window geometry, an AppKit File and Edit menu, and a title bar
  reduced to the Source/Preview control.
- Preview renders GFM — including tables as a true grid — with Markdown
  punctuation hidden and headings scaled by level.
- Folding completed: fold all, unfold all, fence placeholder, per-file
  persistence, and repair across edits.
- A left ribbon rail with a library panel and a full-viewport settings
  surface; theme picker with a hover proxy; theme applied globally.
- Working minimap and zoom; folder tree that populates under the sandbox.
- Stated, testable performance budgets on documents up to 5 MB.
- Text input in Source: caret, selection, undo/redo, dirty wiring.

## Non-goals

As in the planning file. Specifically out of scope for v1.1: new iPhone
or iPad chrome; inline image attachments; fluid typing in 5 MB documents;
side-by-side Source and Preview; PKM, AI, plugins, key remapping; math,
Mermaid, first-class raw HTML preview; Windows or Linux; multi-cursor;
project-wide search; PDF/RTF export; language-aware highlighting inside
fences; list, quote, or `#region` folding; a rope or mmap buffer;
redesigning the six theme palettes.

## Architecture

### Stack

| Layer | Choice | Change from v1 |
|---|---|---|
| Main menu (macOS) | AppKit `NSMenu`, built in `MarkusAppDelegate`, actions routed via the responder chain | **New** |
| App chrome | SwiftUI for ribbon rail, library panel, settings, theme picker | Unchanged |
| Mac documents / tabs | `NSDocument` + tabbed windows hosting `NSHostingController` | Unchanged |
| Editor view | Markus-owned TextKit 2 view (`NSTextContentStorage` + `NSTextLayoutManager` + `NSTextContainer`) | Unchanged |
| Buffer | One `NSTextStorage` holding raw Markdown, authoritative, saved verbatim | Unchanged |
| Preview rendering | `NSTextContentStorageDelegate` paragraph substitution | **New** — replaces attribute-only styling |
| Tables in Preview | Custom-drawn `NSTextAttachment` sized from measured column widths | **New** |
| Text input | Source mode only; `NSTextInputClient` on the Markus view | **New** |
| Parser | cmark-gfm, GFM extensions, Swift wrapper | Unchanged |
| Block index + folds | Swift, derived from parser events; adds persistence and repair | Extended |
| Theme store | One app-scoped store, broadcasting to all open documents | **Changed** — was per-window |
| Persistence | `UserDefaults`: theme, recents, folds per file, zoom, line-number visibility | Extended |

Minimum OS unchanged: macOS 14, iOS 17, iPadOS 17.

### Components

1. **Main menu (macOS).** `NSMenu` hierarchy built at launch. File gets
   New, Open…, Open Folder…, Open Recent, Save, Save As… Edit gets Find,
   Go to Line, Fold All, Unfold All alongside the standard editing items.
   `NSDocumentController` supplies New/Open/Save and populates Open
   Recent automatically. Custom items target `nil` so the responder chain
   resolves them against the active document.
2. **Window geometry.** On `makeWindowControllers`, size and position the
   window to the active screen's `visibleFrame`: three-quarters of its
   width and height, pinned to the top-left corner.
3. **Ribbon rail.** A slim SwiftUI column pinned left of the document,
   with a hamburger at the top toggling the library panel and a gear at
   the bottom opening settings.
4. **Library panel.** The existing folder tree, relocated and toggleable.
   Markdown-only, nested folders, no dotfiles. Enumeration goes through
   the security-scoped **URL**, never a path. Closed by default when only
   a single file is open; opening it with no folder session shows an
   empty state offering Open Folder…
5. **Settings surface.** Fills the viewport. Category list on the left,
   active setting on the right, close box. Not a sheet, not a side pane,
   and not nested inside another `NavigationStack`.
6. **Theme store and picker.** One app-scoped `ThemeStore`. Selection
   broadcasts to every open document. The picker shows six preset cards
   plus custom, above a **single** proxy document; hover previews into
   the proxy only, click applies.
7. **Preview renderer.** An `NSTextContentStorageDelegate` that, in
   Preview mode, returns a substituted `NSTextParagraph` per source
   paragraph: heading sized by level, emphasis and strong applied, list
   and quote shaping via paragraph styles, markup punctuation absent from
   the substituted string. In Source mode it substitutes nothing.
8. **Table attachment.** A GFM table becomes one `NSTextAttachment` whose
   cell measures column widths and draws the grid. It carries the table's
   full source range so selection and copy resolve to Markdown.
9. **Fold services.** Fold all / unfold all over the block index; a fence
   placeholder shown on the opening fence line; per-file fold persistence
   in app storage; fold-ID repair when the index is rebuilt after an edit.
10. **Gutter.** Mode-dependent. Source: a number for every source line.
    Preview: fold chevrons for every foldable block plus a source line
    number at each rendered block's start.
11. **Minimap (macOS).** Reflects document structure, indicates the
    current viewport, scrolls on click, stays fold-aware, and downsamples
    rather than drawing one bar per line.
12. **Text input (Source only).** `NSTextInputClient` conformance on the
    Markus view: caret geometry and blinking, selection drawing, mouse
    drag and double/triple-click selection, keyboard navigation, undo and
    redo, and dirty plus `updateChangeCount` on every mutation including
    undo. Preview is read-only but selectable, and copies source Markdown.
13. **Performance instrumentation.** Test-visible counters — parses
    performed, paragraphs substituted, fragments enumerated per draw — so
    performance is asserted deterministically rather than by wall clock.

### Data model

```text
Document
  url: URL?
  text: NSTextStorage          // raw Markdown, authoritative, saved verbatim
  dirty: Bool
  mode: source | preview       // default preview; editing only in source
  folds: Set<FoldID>           // persisted per file
  zoomScale: CGFloat

FoldID
  kind: heading | fence
  startLine: Int
  anchor: String               // short digest of the block's opening line,
                               // used to repair startLine after an edit

Block                          // unchanged from v1
  id: FoldID
  kind: heading(UInt8) | fence | other
  bytes: Range<Int>
  lines: Range<Int>
  foldExtent: Range<Int>?

SubstitutionCache
  byElementRange: [NSRange: NSTextParagraph]   // invalidated per edited range

TableLayout
  sourceRange: Range<Int>      // full GFM table in source bytes
  columnWidths: [CGFloat]
  rows: [[NSAttributedString]]

Theme                          // app-scoped, not per window
  id: named(String) | custom
  background, tokens, customText
```

The file on disk is `text` only. Folds, mode, theme, zoom, and recents
are never written into the Markdown.

### Key flows

**Open file.** Resolve URL (security scope). Load UTF-8 into
`NSTextStorage`. Parse → block index. Restore persisted folds, repairing
IDs against the current index. Show Preview. Library closed unless a
folder session exists.

**Render Preview.** The layout manager requests an element; the content
storage delegate returns a substituted paragraph built from the block
index and parser spans, or a table attachment. Substitution is lazy —
only what is about to be laid out is built — and cached by element range.

**Switch mode.** Toggle `mode`, invalidate substitutions, relayout. Same
storage, same folds. Never both layouts.

**Toggle fold.** Update `folds`, invalidate layout. **No parse occurs.**
Persist the new fold set for the file.

**Type in Source.** `NSTextInputClient` mutates `NSTextStorage`, registers
undo, publishes dirty and `updateChangeCount`, and moves the caret. The
glyph appears on the next frame. Reparse is debounced and off the
keystroke path; when it completes, the index is rebuilt and fold IDs are
repaired against their anchors.

**Save.** Write the full `text` as UTF-8. Never the folded view, never a
substitution, never Preview output.

**Theme change.** The app-scoped store updates and broadcasts; every open
document restyles.

## Requirements

### Functional

- **R1.** On macOS, a document window opens pinned to the top-left of the
  active screen's `visibleFrame` at three-quarters of its width and
  height.
- **R2.** The File menu contains New, Open…, Open Folder…, Open Recent,
  and Save, with standard shortcuts, all functional. Open Recent is
  populated by `NSDocumentController`.
- **R3.** The Edit menu contains Find, Go to Line, Fold All, and Unfold
  All, with shortcuts.
- **R4.** The document title bar contains the Source/Preview control and
  nothing else. Open, Open Folder, Save, Revert, Recents, Fold, Toggle,
  Find, Go to Line, Tree, and Settings buttons are gone from it.
- **R5.** A left ribbon rail shows a hamburger (top) that toggles the
  library panel and a gear (bottom) that opens settings.
- **R6.** The library panel lists Markdown files (`.md`, `.markdown`,
  `.mdown`, `.mkd`) including nested folders, excluding dotfiles and
  other file types, and **populates under the App Sandbox**. With only a
  single file open it starts closed; opened with no folder session it
  offers Open Folder…
- **R7.** Settings fill the viewport with a category list on the left,
  the active setting on the right, and a working close box.
- **R8.** The theme picker shows six named presets plus custom above a
  single proxy document. Hover previews into the proxy only. Click
  applies. Selection works and persists across relaunch.
- **R9.** A theme applies to **every open window and tab** immediately.
- **R10.** Preview renders GFM as a document: headings scaled by level,
  emphasis and strong applied, lists and block quotes shaped, thematic
  breaks drawn, links presented as links, and Markdown punctuation not
  displayed as literal text.
- **R11.** Tables render as a true grid with aligned columns.
- **R12.** Images are **not** rendered in v1.1; they degrade to readable
  styled text, not raw syntax.
- **R13.** The gutter shows a number for every source line in Source, and
  in Preview shows fold chevrons plus a source line number at each
  rendered block's start. *Revises v1 R6.*
- **R14.** Fold All collapses every foldable block; Unfold All restores
  them. Both are reachable from the Edit menu.
- **R15.** A folded fence shows its opening fence line plus a short
  placeholder.
- **R16.** Folds persist per file across relaunch.
- **R17.** Folds survive an edit elsewhere in the document, repaired
  against their anchors rather than stale line numbers.
- **R18.** The minimap reflects document structure, indicates the current
  viewport, scrolls on click, and stays fold-aware.
- **R19.** Zoom controls visibly change text size in both modes.
- **R20.** In Source, the caret is visible and placeable, typing inserts
  at the caret, selection works by mouse and keyboard, and undo and redo
  work.
- **R21.** The dirty flag and `NSDocument.updateChangeCount` follow every
  text change, including undo and redo.
- **R22.** Preview is read-only but selectable, and copying from it
  yields **source Markdown** — including when the selection covers a
  table.
- **R23.** Save writes the complete unfolded UTF-8 source.

### Non-functional

- **N1.** Native clients only (Swift / AppKit / TextKit 2). Not Electron,
  not a web view.
- **N2.** cmark-gfm is the only parser. The UI does not re-implement GFM.
- **N3.** Folding is a **layout** concern: zero-height owned fragments.
  Never rewrite the buffer; never collapse paragraph styles to hide text.
- **N4.** **One authoritative `NSTextStorage` of raw Markdown.** Preview
  renders by substitution at layout time. Rendered text is never written
  back to the buffer. Markup must not be hidden by clear foreground
  colours or near-zero font sizes — that is the N3 mistake in another
  form.
- **N5.** The AppKit main menu must not break `NSDocument` window
  tabbing. Do **not** add a SwiftUI `WindowGroup` to `MarkusApp`.
- **N6.** macOS is the target; iOS and iPadOS must keep building and
  passing. Any change to the shared editor, parser, or block index
  verifies on all three destinations.
- **N7.** Sandboxed file access uses URL-based APIs. Path-based
  `FileManager` enumeration is forbidden.
- **N8.** Performance is asserted **deterministically** via
  instrumentation counters first, wall-clock second. See Testing
  requirements.
- **N9.** No test may contain an assertion that cannot fail.

### Performance budgets

Measured on macOS. Read-path figures apply to a **saved 5 MB** Markdown
fixture; typing figures apply to a **1 MB** fixture.

| Class | Interactions | Budget |
|---|---|---|
| Continuous | Scrolling, caret movement, drag-selection, minimap drag | **16 ms per frame** (60 Hz) |
| Keystroke | Keystroke to glyph on screen | **16 ms**; reparse must not block it |
| Discrete | Fold/unfold one block, mode switch, go-to-line, outline jump, theme apply, zoom step | **100 ms** |
| Bulk | Fold All, Unfold All, debounced reparse after typing stops | **200 ms** |
| Load | Open a 5 MB document end to end | **1 s**, with first paint within **200 ms** |

Rationale: these are the standard human-factors thresholds — ~100 ms
reads as instantaneous for a direct-manipulation response, ~1 s preserves
flow of thought, and anything continuous is judged per frame rather than
per operation. A single flat figure cannot span both classes.

Structural requirements behind the numbers:

- **P1.** Drawing enumerates only fragments intersecting the visible
  rect. No full-document enumeration per draw.
- **P2.** The gutter computes entries for the visible range only, never
  O(lines × fragments).
- **P3.** Folding, theme changes, zoom steps, mode switches, and
  container resizes perform **zero** parses.
- **P4.** Styling and substitution are lazy and per-element. No
  full-document restyle on any interaction.
- **P5.** `BlockIndex.build` constructs `SourceMap` once per build, not
  once per fenced block.

## Testing requirements

Ticket **Verify:** lines use these commands. Device names match this lab;
adjust only if Xcode changes, and keep three destinations.

Project tests (Mac):

```bash
xcodebuild -project Markus/Markus.xcodeproj -scheme Markus -destination 'platform=macOS' test
```

Project tests (iPhone simulator):

```bash
xcodebuild -project Markus/Markus.xcodeproj -scheme Markus -destination 'platform=iOS Simulator,name=iPhone 17' test
```

Project tests (iPad simulator):

```bash
xcodebuild -project Markus/Markus.xcodeproj -scheme Markus -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M5)' test
```

A ticket touching only macOS-only chrome (menus, window geometry, tabs,
minimap) runs the macOS destination. A ticket changing the shared editor,
parser, block index, or folds must pass **all three**.

There is no `npm test`. Do not invent a web toolchain.

### How to test performance

**Deterministic first.** Expose test-visible counters — parses performed,
paragraphs substituted, fragments enumerated per draw — and assert
against them. These are stable, fast, and cannot flake:

- Folding a block performs **zero** parses (P3).
- Drawing a 5 MB document enumerates a fragment count proportional to the
  viewport, not the document (P1).
- A theme change substitutes only visible paragraphs (P4).

**Wall clock second, with headroom.** Timing assertions on the 5 MB
fixture use a 2× margin over the budget table so ordinary machine noise
does not turn them red. If a timing test proves flaky, convert it to a
counter assertion rather than loosening it indefinitely.

### How to test UI

Assert live behaviour, not compile-time constants. A test that reads
`#if os(macOS) true #else false` back out of a helper proves nothing and
violates N9. Menu items are asserted by validating the built `NSMenu` and
the responder chain resolving each action; panels are asserted through
the view tree or the host state that drives it, with at least one
assertion that would fail if the feature were removed.

## Risks and assumptions

- **The table grid is the main risk.** Substitution is per-paragraph but
  a GFM table spans several source lines, so the grid must live in an
  attachment. Ticket 1 is the hard gate, the way ticket 02 was in v1.
- **Substitution and folding must compose.** Folds collapse layout
  elements; substitution replaces their contents. Both are exercised in
  Preview at once and neither may break the other.
- **Selection across an attachment.** A table is one opaque glyph;
  resolving a selection over it back to source Markdown needs explicit
  handling or R22 fails quietly.
- **Text input on a view that owns its layout manager** is the largest
  single item. There is no `NSTextView` to inherit behaviour from — caret
  geometry, selection drawing, and IME are all bespoke.
- **`updateChangeCount` and dirty** were already unreliable in v1. Wiring
  them from every mutation including undo is a correctness requirement,
  not polish.
- **Timing tests flake.** Hence N8: counters first, wall clock with 2×
  headroom second.
- **5 MB and `NSTextStorage`.** Assumed workable for the read path. If it
  falls over, that reopens the rope/mmap question rather than being
  absorbed into a ticket.
- **Assumption:** one Xcode project, one scheme, three destinations.
- **Assumption:** MIT, no telemetry, no network for core editing.
- **Assumption:** if paragraph substitution cannot meet R10 on this
  stack, reopen design. Do not invent a fourth approach on a ticket.

## Open questions

- **Typing fluency target size.** 5 MB is the *reading* ceiling and
  explicitly not the typing target. This file assumes **1 MB** for the
  typing budget; confirm or replace that figure.
- **Frame budget.** This file assumes **60 Hz / 16 ms** for continuous
  interaction; confirm, or state a different refresh target.
- **Discrete-operation ceiling.** The briefing recorded 200 ms as a base;
  this file proposes **100 ms** for single discrete interactions and
  keeps 200 ms for bulk operations, on the human-factors grounds above.
  Confirm or overrule.
- **Setext headings** remain absent from the outline (carried from v1).
  In scope for ticket 9's mapping work, or still Later?
