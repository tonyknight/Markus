# Markus v1.1 — Completion

> Companion to `(2026-08-16) v1.1 Requirements.md`. Written at board
> completion (14/14 tickets done, merged to `main`) to record what was
> built, what was learned along the way, and what's intentionally left
> for later.

## Summary

All 14 tickets in the v1.1 Tasks Breakdown are `done`, reviewed, and
merged. Project-scope verify (full suite, all three destinations —
macOS, iPhone 17 simulator, iPad Pro 13-inch (M5) simulator) passed
clean on the final merged state. v1.1 delivers: real AppKit window/menu
chrome, a folder library with sandboxed enumeration, working Fold
All/Unfold All with fence placeholders, a full-viewport Settings
surface, a single app-scoped theme with a working card picker, rendered
Preview via TextKit 2 paragraph substitution, a block-anchored Preview
gutter, a structural minimap, per-file fold persistence with anchor
repair, real text editing in Source (caret, selection, undo/redo, dirty
tracking, debounced reparse), and a test-suite integrity pass removing
every assertion that couldn't fail.

## What was done, by ticket

**01 — Table grid spike.** A custom `NSTextAttachment` (`TableAttachment`)
that measures column widths from real cell content and draws an aligned
grid, carries the table's full source byte range for later
selection-to-source mapping, and composes cleanly with fold collapsing.
Hard-gate decision: **GO** — cleared the way for ticket 08's substitution
architecture.

**02 — Window geometry and AppKit main menu.** Launch geometry pinned to
three-quarters of `visibleFrame`, top-left. A real AppKit main menu
(File: New/Open/Open Folder/Open Recent/Save; Edit: Find/Go to
Line/Fold All/Unfold All), custom items resolving through the responder
chain. Fixed a silent-winner bug from two stacked `.fileImporter`
modifiers. Title bar reduced to just the Source/Preview control.

**03 — Folder tree under sandbox.** Markdown-file enumeration
(`.md`/`.markdown`/`.mdown`/`.mkd`, nested, dotfiles excluded) rewritten
to be exclusively URL-based (`FileManager.contentsOfDirectory(at:)`),
never path-based, satisfying the sandbox non-negotiable (N7).

**04 — Fold All/Unfold All and fence placeholder.** Wired Fold
All/Unfold All to the Edit menu over the existing zero-height
`FoldingTextLayoutFragment` mechanism. Folded fences now show their
opening line plus a short `⋯` placeholder instead of collapsing to
nothing.

**05 — Ribbon rail and library panel.** A macOS-only left ribbon rail
(hamburger + gear). The hamburger toggles a library panel hosting
ticket 03's folder tree; starts closed with a single file open; an
empty state offers **Open Folder…** rather than a blank panel.

**06 — Settings surface.** Replaced a broken macOS settings side panel
(a `ToolbarItem` nested inside a `NavigationStack` that got hoisted into
the window toolbar, making its own Done button unreachable) with a
full-viewport `SettingsScene`, sibling to the document `NavigationStack`,
never nested inside it. iOS's already-working sheet-based settings was
left untouched by design.

**07 — Theme proxy and global theme.** Root-caused "theme cards can't be
selected": a SwiftUI `Button` containing an `NSViewRepresentable`
subview silently swallows clicks landing over that subview's region,
even though the subview's own `hitTest` returns `nil`. Fixed by
replacing the embedded live editor sample with a plain SwiftUI-drawn
swatch. Consolidated to one shared `ThemeStore.shared`, broadcasting to
every open window/tab; hover now only ever repaints an isolated proxy
document, never the real open buffer.

**08 — Preview rendering via paragraph substitution.** Real rendered
Preview via a `NSTextContentStorageDelegate` substituting whole
paragraphs at layout time — the buffer stays raw Markdown always (N4).
Found and fixed (twice — once narrowly for fences, then generalized) a
TextKit 2 hang: `NSTextParagraph(attributedString:)` with truly empty
content over a non-empty source range breaks `ensureLayout()`.

**09 — Preview gutter and source mapping.** Source keeps a number per
line; Preview now shows a fold chevron per foldable block plus a source
line number only at each rendered block's start. Found a real bug along
the way: Preview never drew a fence's fold chevron at all (its opening
delimiter has no gutter entry by construction) — fixed generally,
symmetric with click handling.

**10 — Performance to budget.** Viewport-bounded drawing and gutter
computation, zero reparses on fold/theme/zoom/mode-switch, a single
`SourceMap` per `BlockIndex.build`, and deterministic N8 counters. Found
and fixed three real O(n²) bugs via direct process sampling (not
guessing), plus a Critical fold-correctness bug (nested fold extents
need their hidden ranges merged before binary search, or content inside
a fold can leak into view).

**11 — Minimap.** Structural bars (heading/fence/body, not uniform grey),
a real viewport indicator, click-to-scroll, fold-awareness, and
downsampling capped at 512 bars regardless of document size. Found and
closed a real staleness hole: several fold/mode/zoom mutators bypassed
`onTextDidChange`, so the minimap (and anything else observing document
state) could silently go stale after a real chevron click.

**12 — Fold persistence and repair.** `FoldID` gained an `anchor` (a
digest of the block's opening line). Folds persist per file in
`UserDefaults` (not an in-memory `Set`) and are repaired against their
anchors — not stale line numbers — whenever the block index rebuilds,
so a fold survives an edit made elsewhere in the document.

**13 — Text input in Source** (the largest ticket in the release).
`NSTextInputClient` conformance with real IME/dictation support, caret
geometry and blinking; mouse click/drag/double/triple-click selection
plus keyboard navigation; undo/redo coalescing; `NSDocument
.updateChangeCount` wiring including undo/redo; debounced reparse off
the keystroke path integrated with ticket 12's fold repair; a
Preview-selection-to-source-Markdown reverse mapping including
multi-table selections; an accessibility pass; a rewritten
keystroke-to-glyph performance test. Two review rounds; four Important
findings from the first (undo/redo unreachable by any real keyboard
shortcut, arrow-key movement not skipping folded ranges, an untested
dirty/undo round-trip claim, Preview accessibility reading raw Markdown
instead of rendered text) were all found, fixed, and re-verified.

**14 — Test integrity pass.** Audited the whole suite for assertions
that can't fail (N9). Deleted `MacOnlyChromeTests.swift` and several
other `#if os(macOS) true #else false #endif`-shaped tautologies
(including two the plan's own audit missed, found by the implementer's
own follow-up grep). Replaced the one case with no redundant live
coverage elsewhere (`ModeChromeTests`) with a real test that materializes
a window/toolbar and inspects the actual view subtree for the segmented
control, modeled on an existing precedent in the suite.

## What we found out

A handful of findings recurred across tickets and are worth keeping in
mind for future work on this codebase:

- **TextKit 2 does not tolerate truly empty substituted paragraphs.**
  `NSTextParagraph(attributedString:)` with zero-length content over a
  non-empty source range hangs `ensureLayout()`. Ticket 08's fix
  normalizes any zero-length rendered content to a single space.
- **SwiftUI `Button` + embedded `NSViewRepresentable`/`UIViewRepresentable`
  silently swallows clicks** landing over the embedded subview's region,
  even when that subview's own `hitTest` returns `nil`. Ticket 07 traced
  this empirically (isolated via a throwaway harness dispatching real
  `NSEvent`s) rather than assuming — worth remembering before embedding
  a platform view inside any tappable SwiftUI control again.
- **Folded/hidden UTF-16 ranges must be merged before binary search.**
  Fold extents can nest (a heading containing a nested block's own fold
  extent); searching unmerged, possibly-overlapping ranges is incorrect
  and was a real, empirically-confirmed Critical bug (ticket 10).
- **Direct process sampling (`sample <pid>`) beats guessing.** Every
  suspiciously slow test run in this project was eventually traced with
  `sample`, grepping `Markus.` frames by frequency — this found three
  real O(n²) bugs in ticket 10 quickly, after ticket 08 initially wasted
  time chasing a phantom "build service" hang that was actually a real
  code bug. Established as the standard first response in this project.
- **A feature can be internally correct and still be unreachable.**
  Ticket 13's undo/redo mechanism was fully implemented, tested, and
  reviewed clean on the first pass — but no keyboard shortcut or menu
  item actually invoked it, so no real user could reach it. Caught by a
  dedicated review pass, not by the implementation's own tests (which,
  reasonably, only tested the mechanism they'd built).
- **Counters over wall-clock, always.** This project's N8 preference
  (deterministic instrumentation counters as the primary proof of
  performance properties, wall-clock as a secondary, generously-margined
  check) held up well — several wall-clock tests were flaky under this
  Mac's parallel test execution (`parallelizable="YES"`, 10-30x slowdown
  from worker contention) purely from environmental noise, while counter
  assertions stayed stable throughout.

## Known gaps and follow-ups

Nothing below blocked any ticket from being marked done — each was
either explicitly out of scope, judged Minor by a review pass, or is a
deliberate, disclosed scope boundary. Listed here so they aren't lost.

- **Preview-mode accessibility for tables and thematic breaks** reads as
  a bare object-replacement character (U+FFFC) to VoiceOver rather than
  real content — headings/paragraphs/lists read correctly as rendered
  text (ticket 13's T07 fix), but table cell text and thematic-break
  markup do not. Real, disclosed gap; a fast-follow ticket would close
  it.
- **`ThemeChrome.showsHoverPreview`'s cross-platform gating is
  untested** — the implementer's rationale (a single-platform test
  binary can't exercise both sides of a compile-time branch) was judged
  by review to overstate its case; a real single-platform live test was
  buildable and wasn't written. Left as a note for future maintainers,
  not a blocker (ticket 14).
- **A handful of Minor findings from ticket 13's first review round were
  deliberately left as-is**: a latent undo-manager crash risk if a
  future ticket wires standard Cmd+Z through the responder chain rather
  than `keyDown` directly; `tableSourceRanges` (plural) going unused in
  production; debounce tests that bypass the real timer; a theoretical
  timer double-fire race. None reproduced; all disclosed in the ticket's
  Notes for whoever touches that code next.
- **Real macOS App Sandbox permission denial was never exercised.**
  Ticket 03's regression test proves enumeration is exclusively
  URL-based via an injectable lister, but a genuine sandbox denial
  couldn't be reproduced deterministically in this automated
  environment — every fixture location behaved identically with or
  without an active security scope. True denial needs a folder outside
  all static entitlements, reachable only via an interactive
  `NSOpenPanel` grant.
- **Typing fluency at 5 MB is explicitly out of scope** (Constraints);
  only the 1 MB keystroke-to-glyph budget was targeted and met (ticket
  13's T08).
- **Undo/Redo have no Edit-menu item**, only the Cmd+Z/Cmd+Shift+Z
  keyboard shortcuts added in ticket 13's review-fix round. Functionally
  complete per R20, but a menu entry would be the more conventional
  AppKit affordance if that's ever wanted.
- **`docs/ai/Markus/v1.1/tickets/20260816-08-...md` has a harmless,
  pre-existing lint mismatch** (`current_task 'T08'` doesn't match a
  task id in that ticket's own plan) that predates this release's work
  on it, caused by a mid-project `bora` CLI version bump to 0.7.5
  introducing a stricter linter. Confirmed via `git stash` against
  earlier commits. Cosmetic; does not affect the app.
- **`bora` itself has drifted**: this repo's `AGENTS.md` was written
  against an older `bora` version than the 0.7.5 CLI now installed
  (`bora dev upgrade` was never run mid-project, to avoid destabilizing
  an in-flight execute run). Worth reconciling before the next project.
